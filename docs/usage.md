# 使い方（詳細）

README の[使い方](../README.md#使い方)に入りきらない、設定項目や書き方の詳細です。

## お気に入り

よく使うシェル構成（シェル種別・起動ディレクトリ・引数・環境変数）を保存し、ワンクリックで新しいタブとして起動できる機能です。左サイドバー下部の **Favorites** セクションに一覧表示されます。

<!-- SCREENSHOT: お気に入り一覧と設定ダイアログ (docs/images/favorites.png) -->

**登録する方法は 2 通り:**

1. **既存タブから登録（かんたん）** — タブを右クリック →「お気に入りに追加」。今開いているタブのシェル・ディレクトリ・引数・環境変数がそのまま引き継がれます。
2. **新規登録** — Favorites セクションの **`+ Add Favorite`** ボタンから、設定ダイアログを開いて手動入力します。

**登録後の操作（お気に入りを右クリック）:**

- **ここから spawn** — 設定内容で新しいタブを起動（クリックでも起動します）
- **編集** — 設定を変更
- **既定として設定 / 既定を解除** — 既定にすると ⭐ アイコンになり、`Ctrl+T`（既定タブを開く）で起動するシェルになります
- **削除**

お気に入りは D&D で並び替えでき、`Ctrl+Shift+1〜9` で上から 1〜9 番目をすばやく起動できます。

**設定ダイアログの項目:**

| 項目 | 必須 | 内容 |
|---|---|---|
| テンプレート | 任意 | 選択すると `タイトル`・`Shell`（一部は引数）を自動入力。WSL ディストロは自動検出され候補に並びます。あくまで雛形で、後から上書き編集できます |
| タイトル | **必須** | お気に入りの表示名 |
| Shell | 任意 | 例: `wsl.exe` / `pwsh.exe` / `cmd.exe`。**空欄なら既定シェル（nushell）** |
| WSL ディストリビューション | WSL 時 | `Shell` に `wsl.exe` を選ぶと表示。インストール済み distro から選択（取得できない場合は手入力） |
| 作業ディレクトリ (Linux パス) | WSL 時 | 同上。`-d` / `--cd` は自動で組み立てられるため手書き不要 |
| CWD | 任意 | 起動ディレクトリ。例: `C:\Users\foo\projects`。**空欄ならホーム** |
| 引数 | 任意 | シェル起動時に渡すコマンドライン引数 → [書き方](#引数の書き方)。WSL は簡易フォームと手動引数モードを切り替えできます |
| 環境変数 | 任意 | `KEY=VALUE` 形式の環境変数 → [書き方](#環境変数の書き方) |
| Claude Code を自動起動 | 任意 | → [Claude Code の自動起動](#claude-code-の自動起動) |
| 権限プロンプトをバイパス | 任意 | 上記が ON のときだけ表示。→ 同上 |
| タブ名のデフォルト | 任意 | お気に入りタイトルと別のタブ名にしたい場合に指定。空欄ならタイトルを流用 |

## Claude Code の自動起動

お気に入り編集画面の **「Claude Code を自動起動する」** を ON にすると、そのお気に入りから開いたタブで `claude` が自動的に起動します。

- **セッション再開** — アプリを再起動してタブが復元されるとき、前回の claude セッションの続きから自動で再開します。セッション名はタブ名／作業フォルダ名から自動付与されます。
- **手動で起動した claude も再開** — 自動起動が OFF のタブでも、自分で `claude` と打って使っていたセッションを再起動時に再開します。ただし **復元されるのは、Racker を終了した時点で claude が動いていたタブだけ**です（自分で `/exit` していたタブは素のシェルで開きます）。また、この経路では **権限バイパス（`--dangerously-skip-permissions`）は引き継ぎません** — 手動起動時に付けたオプションはセッションに残らないため、推測で権限を緩めない方針です。追跡できないケースは下の「手動で起動した claude の復元」を参照してください。
- **WSL の場合** — シェルにコマンドをタイプ送信するのではなく `claude` を直接 exec します。WSL のコールド起動が遅い環境でも取りこぼしません。claude を終了すると通常のログインシェルに戻るので、タブはそのまま使い続けられます。
- **権限プロンプトのバイパス** — 自動起動を ON にすると下に「権限プロンプトをバイパスする」チェックボックスが出ます。ON にすると `claude --dangerously-skip-permissions` で起動し、ファイル編集・コマンド実行の確認をスキップします。既定は OFF です。

> ⚠️ **権限バイパスは信頼できる作業ディレクトリ専用にしてください。** Claude が確認なしにファイル編集・コマンド実行を行います。
>
> ℹ️ これらの設定は**新しく開いたタブから有効**です。すでに開いているタブには遡及しません。


### 手動で起動した claude の復元

**自分で `claude` と打って起動したタブも追跡されます。** Racker は起動中の Claude Code セッションを検出してタブと結びつけるため、自動起動を使っていないタブでも再起動後に同じセッションから再開できます。

手動で起動した claude の復元には、次の但し書きがあります。

- **自分で claude を終了（`/exit`）していた場合は復元しません。** 復元されるのは、Racker を終了した時点で claude が動いていたタブだけです。
- **PowerShell / cmd / Git Bash で `cd` した先で claude を起動した場合は追跡できません。** これらのシェルは作業ディレクトリの変更を Racker に通知しないため、タブの起動ディレクトリのままだと判断してしまうからです（既定の Nushell は `cd` に追従します）。
- **同じフォルダで Racker 以外の claude（VS Code など）が動いている場合、そちらのセッションを再開することがあります。** セッションファイルは「どのアプリが起動したか」を持たないため、フォルダの一致でしか結びつけられません。意図しないセッションを掴んでいたら、タブを右クリック →「Claude セッションの記録を消す」でやり直せます。
- **最終更新から 3 日以上経った古いセッションは復元対象にしません。** 特に WSL では、強制終了した claude のセッションファイルが何ヶ月も残るためです。
- **WSL タブは、起動引数に distro（`-d`）が入っている必要があります。** お気に入り編集画面から作った WSL タブには自動で入るので、通常は意識する必要はありません（引数を手で書き換えて `-d` を消した場合だけ、追跡できなくなります）。

## 引数の書き方

「引数」はシェルを起動するときに渡すコマンドライン引数です。**1 行に 1 つずつ**書くのがルールです。

ふだんターミナルでスペース区切りに打つ引数も、この欄では**改行して 1 つずつ分けて**書きます。

**例) WSL をホームディレクトリで起動したい**

ターミナルで打つコマンドはこうですが：

```
wsl.exe --cd ~
```

Racker Terminal のお気に入りでは、`Shell` 欄に `wsl.exe`、`引数` 欄に次のように **2 行**で書きます：

```
--cd
~
```

| 書き方 | 結果 |
|---|---|
| ✅ `--cd` と `~` を**別々の行** | `--cd` と `~` の 2 つの引数として正しく渡る |
| ❌ `--cd ~` を**1 行にまとめる** | 全体が 1 つの引数 `"--cd ~"` とみなされ、正しく動かない |

> 空行や前後の空白だけの行は無視されます。
>
> WSL の場合は簡易フォーム（distro + Linux パス）を使えば、この書き方を覚える必要はありません。

## 環境変数の書き方

環境変数は **1 行に 1 つ、`KEY=VALUE` 形式**で書きます。

```
NODE_ENV=development
PATH=C:\custom\bin;%PATH%
```

- `KEY` は `A〜Z`・`a〜z`・`_` で始まり、英数字と `_` のみ使えます（POSIX 慣例）。不正な行があると保存時にエラー表示されます。
- ⚠️ env は**平文で保存**されます。API キー・パスワード等の機密値は入れないでください（[機密値の取り扱い注意](#機密値の取り扱い注意)）。

## フォルダを選んで開く（お気に入り不要）

お気に入りに登録していない**臨時のフォルダ**を、その場で選んで開けます。サイドバー下部の **📁 ボタン** を押すと、シェル一覧（Nushell / PowerShell / Command Prompt / Git Bash / WSL: 各ディストリビューション）が表示されます。シェルを選ぶと **Windows のフォルダ選択ダイアログ（エクスプローラー UI）** が開き、フォルダを選ぶとそのシェルで選択フォルダを作業ディレクトリにした新しいタブが開きます。

- **Windows ネイティブシェル**（Nushell / PowerShell / cmd / Git Bash）: 選んだフォルダを作業ディレクトリにして起動します。
- **WSL**: 選んだ Windows パスを `wsl.exe --cd <パス>` に渡します。`wsl.exe` が Windows パスを Linux パスへ自動変換して着地するため、`/mnt/...` を手入力する必要はありません。

インストール済みの WSL ディストリビューションはシェル一覧に自動で並びます（`wsl.exe` 未導入の環境では WSL 項目は出ません）。

## 永続化される情報

アプリ再起動後も、タブ・グループ・お気に入りの構成が復元されます（localStorage に保存）。

| 情報 | 永続化 | 備考 |
|---|---|---|
| タブ・グループ・お気に入りの構成 | ✅ | |
| shell / cwd / 環境変数 | ✅ | 起動時に再 spawn |
| Claude Code のセッション | ✅ | 自動起動 ON のタブ、および終了時に claude が動いていたタブは前回セッションから再開（自分で `/exit` したタブ・最終更新から 3 日以上経ったセッションは対象外） |
| ユーザー編集したタブ名 (userTitle) | ✅ | OSC タイトルより優先 |
| Settings（フォント等） | ✅ | サイドバーフッタの ⚙ から変更 |
| scrollback（PTY 出力履歴） | ✅ | **表示のみ**復元（直近 1000 行）。プロセスは復活しないため、区切り線から下が新しいセッション |
| 実行中状態（active タブ・編集中） | ❌ | ランタイム情報 |
| shell 側の OSC タイトル | ❌ | 起動後に shell が再送信 |

## 機密値の取り扱い注意

お気に入りの `env`（環境変数）は **localStorage に平文 JSON で保存**されます。WebView2 の DevTools や `%LOCALAPPDATA%\<app>\EBWebView\` の LevelDB から読み取れる可能性があります。

**API キー・パスワード・個人トークン等の機密値は env に入れないでください。** 将来 OS keyring（Windows Credential Manager 等）への退避を検討中です。
