## v1.9.11

**自分で `claude` と打って使っていたタブも、再起動で会話の続きから開くようになりました。**

### 修正

- **手動で起動した Claude Code のセッションが復元されない問題**: 「Claude Code を自動起動」を ON にしていないお気に入りから開いたタブで、自分で `claude` と打って作業していると、racker を再起動したときに会話が途切れていました。説明書きでは以前から「自動起動を使っていないタブでも再開できます」としていましたが、実際には動いていませんでした。

  今回から、**終了した時点で Claude が動いていたタブ**を、次の起動で同じ会話から開き直します。**自分で Claude を終了（`/exit`）していたタブは、これまでどおり素のシェルで開きます** — 終わらせたつもりのタブが勝手に立ち上がることはありません。

- **WSL タブの状態ドットがちらつく問題**: WSL のタブでは、Claude の状態表示が数秒おきに消えては戻る動きをしていました。WSL の中を見に行くのは負荷が高いため 10 秒に 1 回に間引いているのですが、見に行かなかった回を「Claude が終了した」と誤って判断していたのが原因です。ステータスバーのモデル名やコンテキスト量の表示も、同じ理由で点滅しなくなります。

- **タブを右クリックしてお気に入りに追加すると、Claude の設定が外れる問題**: Claude タブをお気に入りに登録しても、「Claude Code を自動起動」と「権限プロンプトをバイパスする」が引き継がれず、次に開いたときに Claude が起動しないお気に入りになっていました。

### 新機能

- **タブの右クリックに「Claude セッションの記録を消す」を追加**: racker は、同じフォルダで動いている Claude を見つけてタブと結びつけます。この結びつけを間違えたとき（同じフォルダで VS Code など別のアプリの Claude も動いていた場合など）に、記録を外してやり直せます。Claude を使っていないタブには表示されません。

### 補足

- **PowerShell / cmd / Git Bash で `cd` した先で Claude を起動した場合は追跡できません。** これらのシェルは作業フォルダの移動を racker に伝えないためです。既定の Nushell は移動に追従するので、`cd` してから `claude` と打っても復元されます。
- **同じフォルダで racker 以外の Claude が動いている場合、そちらの会話を再開することがあります。** セッションの情報には「どのアプリが起動したか」が残らないため、フォルダの一致でしか結びつけられません。意図しない会話を掴んでいたら、上記の「Claude セッションの記録を消す」でやり直せます。
- **最終更新から 3 日以上経った古いセッションは復元しません。** とくに WSL では、強制終了した Claude の記録が何ヶ月も残り続けるためです。
- 手動で起動したタブの復元では、**権限プロンプトのバイパス（`--dangerously-skip-permissions`）は引き継ぎません。** 手動で打ったときに付けていたかどうかが記録に残らないため、推測で権限を緩めない方針です。
- この更新の直後の 1 回だけ、更新前に溜まっていた古い記録は復元に使いません。以前は記録を消す手段が無く、何ヶ月も前に一度 Claude を打っただけのタブにも残っていたためです。次に Claude を使えば、その時点から通常どおり追跡されます。
