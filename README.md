# Racker Terminal

**Windows で Claude Code を回すためのターミナル。**

プロジェクトごとの起動設定をワンクリックで開き、アプリを再起動しても **Claude のセッションの続きから**復元します。

<!-- SCREENSHOT: ここにメインスクリーンショット (docs/images/hero.png) を挿入 -->

- **Windows 専用**（Windows 10 1809+ / Windows 11）
- **Electron ではありません** — Tauri 2（WebView2 + Rust）製
- **アカウント登録なし・テレメトリなし・クラウド送信なし** — 設定は端末内に閉じます

## なぜ Racker か

### 1. プロジェクトの起動設定を「お気に入り」に畳む

シェル種別・起動ディレクトリ・引数・環境変数をひとまとめに保存して、サイドバーからワンクリック起動。`Ctrl+Shift+1〜9` で 1〜9 番目を直接開けます。WSL なら distro とディレクトリを選ぶだけで、`-d` や `--cd` は自動で組み立てられます。

### 2. 再起動しても、Claude の続きから

「Claude Code を自動起動」を ON にしたお気に入りから開いたタブは、`claude` が自動で立ち上がります。さらに **アプリを再起動してタブが復元されるとき、前回の claude セッションの続きを自動で再開**します（タブごとに専用セッションを保持）。PC を再起動するたびに WSL を開いて `cd` して `claude --resume` を打ち直す作業が消えます。

### 3. Claude が呼んでいるタブが光る

非アクティブなタブで Claude Code が処理完了・入力待ちになると（BEL 検知）、サイドバーの該当タブに**オレンジのリングと pulse アニメーション**が出ます。折りたたんだグループの中にあってもグループヘッダに出るので、複数プロジェクトを並行で回していても「どれが自分を待っているか」が一目で分かります。

### 4. Windows と WSL の面倒を吸収する

| こまごました詰まり | Racker の挙動 |
|---|---|
| Claude Code に改行を入れたい | `Ctrl+Enter` で ESC+CR を送出（Mac の `Option+Enter` 相当） |
| 画像やファイルを Claude に渡したい | ウィンドウにドロップするとパスが type される。**WSL タブなら `/mnt/c/...` へ自動変換**、スペース入りは自動クオート |
| 出力された URL を開きたい | `Ctrl+クリック`（`http:` / `https:` のみ、`javascript:` 等は無視） |
| 選択したテキストをコピーしたい | `Ctrl+C`（選択なしのときは従来どおり SIGINT） |
| 音声入力ツールから貼り付けたい | Aqua Voice 等の合成キー入力に対応（クリップボード経由 / `Ctrl+V` モード） |

## 他のターミナルとの違い

|  | **Racker** | Windows Terminal | WezTerm | [herdr](https://herdr.dev/) |
|---|---|---|---|---|
| Claude Code の自動起動 | ✅ | ❌ | ❌ | ❌（手動で起動） |
| 再起動後のセッション再開 | ✅ claude の続きから | ❌ | ❌ | ✅ サーバ常駐で維持 |
| エージェントの待ち状態通知 | ✅ タブが光る | ❌ | ❌ | ✅ 状態サイドバー |
| プロジェクト別ワンクリック起動 | ✅ お気に入り | △ プロファイル | △ 設定ファイル | ✅ |
| 再起動後のタブ構成復元 | ✅ | ❌ | ❌ | ✅ |
| WSL パスの自動変換 D&D | ✅ | ❌ | ❌ | — |
| 設定方法 | **GUI ダイアログ** | JSON | Lua | TOML / CLI |
| ペイン分割 | ❌ | ✅ | ✅ | ✅ |
| SSH / リモート | ❌ | — | ✅ | ✅ |
| 対応 OS | Windows のみ | Windows | クロスプラットフォーム | Linux / macOS / Windows (beta) |

**向いている人** — Windows + WSL で Claude Code を複数プロジェクト並行で回している / tmux のキーバインドを覚える気はなくマウスとサイドバーで完結させたい / 設定ファイルを書かずに GUI で済ませたい。

**向いていない人** — ペイン分割が必須 / SSH 先で使いたい / macOS・Linux も使う / ターミナルを細かくカスタマイズしたい（Racker は設定項目を意図的に絞っています）。SSH 越しに複数エージェントを回したいなら [herdr](https://herdr.dev/) の方が適任です。

## インストール

[リリースページ](https://github.com/kogasura/racker-terminal/releases/latest)から `Racker Terminal_<version>_x64-setup.exe` (NSIS) をダウンロードし、ダブルクリックでインストール → スタートメニューから起動。

### ⚠️ SmartScreen の警告が出ます（想定どおりです）

**Racker は Authenticode コード署名を行っていないため、初回起動時に Windows Defender SmartScreen の青い警告画面が出ます。**

```
「WindowsによってPCが保護されました」
→ 「詳細情報」をクリック
→ 「実行」をクリック
```

これは「怪しいから止められている」のではなく、**署名証明書を購入していない個人開発アプリすべてに出る**警告です（EV 証明書は年間数万円かかり、個人 OSS では現実的でないため見送っています）。

不安な場合は以下で確認できます：

- **ソースは全公開**です。このリポジトリをクローンして `npm run tauri build` で自分でビルドできます
- 配布物は GitHub Releases 経由のみで、他の配布経路はありません
- ダウンロードした exe のハッシュは PowerShell で確認できます:
  ```powershell
  Get-FileHash "$env:USERPROFILE\Downloads\Racker Terminal_1.7.0_x64-setup.exe" -Algorithm SHA256
  ```

将来的にコード署名を導入した場合は、この項目を削除します。

### 必要環境

- Windows 10 (build 1809) 以降 / Windows 11
- WebView2 ランタイム（Windows 11 はプリインストール、Windows 10 は自動ダウンロード）
- フォント: **MonaspiceNe NF はバンドル済**（Cascadia Code / Consolas にフォールバック可）
- Claude Code の自動起動を使う場合: `claude` が PATH にあること

### アップデート

**v1.1 以降は起動時・起動中（1 時間ごと）に自動で更新を確認します。** 新しいバージョンがある場合、タイトルバーに更新ボタンが表示されます。クリックするとリリースノートを確認した上で、承認制でダウンロード・インストール・再起動が行われます。設定ダイアログの「バージョン情報」からも手動でチェックできます。詳細は [docs/auto-update.md](docs/auto-update.md) を参照。

### v1.0.x で MSI 版を使っていた方へ

v1.1 から MSI インストーラーは廃止し、NSIS インストーラー (`setup.exe`) のみの配布になりました。`setup.exe` を実行すると新しい場所に v1.1 がインストールされます（旧 MSI 版とは別の場所）。旧 MSI 版が不要なら、Windows の「設定 → アプリ → インストールされているアプリ」から旧バージョン (1.0.x) をアンインストールしてください。

## 使い方

### お気に入り

よく使うシェル構成（シェル種別・起動ディレクトリ・引数・環境変数）を保存し、ワンクリックで新しいタブとして起動できる機能です。左サイドバー下部の **Favorites** セクションに一覧表示されます。

<!-- SCREENSHOT: お気に入り一覧と設定ダイアログ (docs/images/favorites.png) -->

**登録する方法は 2 通り:**

1. **既存タブから登録（かんたん）** — タブを右クリック →「お気に入りに追加」。今開いているタブのシェル・ディレクトリ・引数・環境変数がそのまま引き継がれます。
2. **新規登録** — Favorites セクションの **`+ Add Favorite`** ボタンから、設定ダイアログを開いて手動入力します。

**登録後の操作（お気に入りを右クリック）:**

- **ここから spawn** — 設定内容で新しいタブを起動（クリックでも起動します）
- **編集** — 設定を変更
- **既定として設定 / 既定を解除** — 既定にすると ⭐ アイコンになり、`Ctrl+T`（既定タブを開く）で起動するシェルになります
- **削除**

お気に入りは D&D で並び替えでき、`Ctrl+Shift+1〜9` で上から 1〜9 番目をすばやく起動できます。

**設定ダイアログの項目:**

| 項目 | 必須 | 内容 |
|---|---|---|
| テンプレート | 任意 | 選択すると `タイトル`・`Shell`（一部は引数）を自動入力。WSL ディストロは自動検出され候補に並びます。あくまで雛形で、後から上書き編集できます |
| タイトル | **必須** | お気に入りの表示名 |
| Shell | 任意 | 例: `wsl.exe` / `pwsh.exe` / `cmd.exe`。**空欄なら既定シェル（nushell）** |
| WSL ディストリビューション | WSL 時 | `Shell` に `wsl.exe` を選ぶと表示。インストール済み distro から選択（取得できない場合は手入力） |
| 作業ディレクトリ (Linux パス) | WSL 時 | 同上。`-d` / `--cd` は自動で組み立てられるため手書き不要 |
| CWD | 任意 | 起動ディレクトリ。例: `C:\Users\foo\projects`。**空欄ならホーム** |
| 引数 | 任意 | シェル起動時に渡すコマンドライン引数 → [書き方](#引数の書き方)。WSL は簡易フォームと手動引数モードを切り替えできます |
| 環境変数 | 任意 | `KEY=VALUE` 形式の環境変数 → [書き方](#環境変数の書き方) |
| Claude Code を自動起動 | 任意 | → [Claude Code の自動起動](#claude-code-の自動起動) |
| 権限プロンプトをバイパス | 任意 | 上記が ON のときだけ表示。→ 同上 |
| タブ名のデフォルト | 任意 | お気に入りタイトルと別のタブ名にしたい場合に指定。空欄ならタイトルを流用 |

### Claude Code の自動起動

お気に入り編集画面の **「Claude Code を自動起動する」** を ON にすると、そのお気に入りから開いたタブで `claude` が自動的に起動します。

- **セッション再開** — アプリを再起動してタブが復元されるとき、前回の claude セッションの続きから自動で再開します。セッション名はタブ名／作業フォルダ名から自動付与されます。
- **WSL の場合** — シェルにコマンドをタイプ送信するのではなく `claude` を直接 exec します。WSL のコールド起動が遅い環境でも取りこぼしません。claude を終了すると通常のログインシェルに戻るので、タブはそのまま使い続けられます。
- **権限プロンプトのバイパス** — 自動起動を ON にすると下に「権限プロンプトをバイパスする」チェックボックスが出ます。ON にすると `claude --dangerously-skip-permissions` で起動し、ファイル編集・コマンド実行の確認をスキップします。既定は OFF です。

> ⚠️ **権限バイパスは信頼できる作業ディレクトリ専用にしてください。** Claude が確認なしにファイル編集・コマンド実行を行います。
>
> ℹ️ これらの設定は**新しく開いたタブから有効**です。すでに開いているタブには遡及しません。

### 引数の書き方

「引数」はシェルを起動するときに渡すコマンドライン引数です。**1 行に 1 つずつ**書くのがルールです。

ふだんターミナルでスペース区切りに打つ引数も、この欄では**改行して 1 つずつ分けて**書きます。

**例) WSL をホームディレクトリで起動したい**

ターミナルで打つコマンドはこうですが：

```
wsl.exe --cd ~
```

Racker Terminal のお気に入りでは、`Shell` 欄に `wsl.exe`、`引数` 欄に次のように **2 行**で書きます：

```
--cd
~
```

| 書き方 | 結果 |
|---|---|
| ✅ `--cd` と `~` を**別々の行** | `--cd` と `~` の 2 つの引数として正しく渡る |
| ❌ `--cd ~` を**1 行にまとめる** | 全体が 1 つの引数 `"--cd ~"` とみなされ、正しく動かない |

> 空行や前後の空白だけの行は無視されます。
>
> WSL の場合は簡易フォーム（distro + Linux パス）を使えば、この書き方を覚える必要はありません。

### 環境変数の書き方

環境変数は **1 行に 1 つ、`KEY=VALUE` 形式**で書きます。

```
NODE_ENV=development
PATH=C:\custom\bin;%PATH%
```

- `KEY` は `A〜Z`・`a〜z`・`_` で始まり、英数字と `_` のみ使えます（POSIX 慣例）。不正な行があると保存時にエラー表示されます。
- ⚠️ env は**平文で保存**されます。API キー・パスワード等の機密値は入れないでください（[機密値の取り扱い注意](#機密値の取り扱い注意)）。

## キーボードショートカット

| ショートカット | 動作 |
|---|---|
| `Ctrl+T` | 既定タブ（既定のお気に入り）を開く |
| `Ctrl+Shift+T` | 閉じたタブを復元（最大 10 個まで履歴保持、再起動でクリア） |
| `Ctrl+Shift+W` | アクティブタブを閉じる |
| `Ctrl+Tab` / `Ctrl+Shift+Tab` | 次 / 前のタブへ移動 |
| `Ctrl+Shift+1〜9` | お気に入りの 1〜9 番目を開く |
| `Ctrl+C` | 選択範囲をコピー（選択なしのときは従来通り SIGINT） |
| `Ctrl+V` | クリップボードから貼り付け |
| `Ctrl+Enter` | 改行を挿入（ESC+CR を送出。Mac Terminal の `Option+Enter` 相当で、Claude Code 等の readline CLI が改行として認識する） |
| `Ctrl+クリック` | ターミナル上の URL を既定ブラウザで開く（`http:` / `https:` のみ。`javascript:` / `file:` / `data:` 等は無視） |

ターミナルへのファイルのドラッグ＆ドロップで、ファイルパスを貼り付けできます（WSL タブでは `/mnt/c/...` 形式へ自動変換）。

## 永続化される情報

アプリ再起動後も、タブ・グループ・お気に入りの構成が復元されます（localStorage に保存）。

| 情報 | 永続化 | 備考 |
|---|---|---|
| タブ・グループ・お気に入りの構成 | ✅ | |
| shell / cwd / 環境変数 | ✅ | 起動時に再 spawn |
| Claude Code のセッション | ✅ | 自動起動 ON のタブは前回セッションから再開 |
| ユーザー編集したタブ名 (userTitle) | ✅ | OSC タイトルより優先 |
| Settings（フォント等） | ✅ | サイドバーフッタの ⚙ から変更 |
| scrollback（PTY 出力履歴） | ❌ | PTY と一蓮托生のため復元不可 |
| 実行中状態（active タブ・編集中） | ❌ | ランタイム情報 |
| shell 側の OSC タイトル | ❌ | 起動後に shell が再送信 |

## 機密値の取り扱い注意

お気に入りの `env`（環境変数）は **localStorage に平文 JSON で保存**されます。WebView2 の DevTools や `%LOCALAPPDATA%\<app>\EBWebView\` の LevelDB から読み取れる可能性があります。

**API キー・パスワード・個人トークン等の機密値は env に入れないでください。** 将来（Phase 5+）で OS keyring（Windows Credential Manager 等）への退避を検討中です。

## 制約 / 方針

- **Windows 専用**、クロスプラットフォーム非対応
- ユーザー設定項目は最小限（フォント・配色・既定シェルは「押し付けるデフォルト」）
- ペイン分割なし、シングルウィンドウ
- SSH / リモート接続機能なし
- 内部（端末描画・PTY）は成熟ライブラリを使い、UI だけを作り込む方針
