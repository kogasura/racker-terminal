## v1.9.6

**WSL タブでも、Claude Code が提示した画像やファイルを Ctrl+クリックで開けるようになりました。**

### 修正

- **WSL タブで画像・ファイル参照が開けなかった問題を修正しました**: v1.9.5 でこの機能を入れましたが、実際に効いていたのは Windows 側のタブ（PowerShell / Git Bash / cmd）だけで、WSL タブでは `[image] /tmp/…/slide.001.png` のようなテキストのままでした。

  原因は 2 つありました。1 つは「この端末はリンク対応」という合図が WSL の中まで届いていなかったこと。もう 1 つは、WSL の中のパス（`/tmp/…` や `/home/…`）を Windows 側から開く手立てが無かったことです。今回、合図が WSL の中まで届くようにし、WSL 内のパスも `\wsl.localhost\<distro>\…` として開けるようにしました。

  これまでどおり、**Ctrl を押しながらクリック**（Mac のキーボードでは Cmd+クリック）で開きます。画像・PDF・Markdown などはいつものアプリで開き、ソースコードや実行ファイルはエクスプローラーで場所を表示するだけに留めます。

- **WSL タブの色表現の指定も届くようになりました**: これまで WSL の中のコマンドには 24bit カラー対応の合図（`COLORTERM`）が渡っていませんでした。ツールによっては色数が控えめになっていた可能性があります。

### 補足

- WSL タブの distro は、タブの起動引数（`-d <名前>`）から判断します。`-d` を付けていないタブでは既定の distro を使います。
- PowerShell タブなどから手で `wsl` と打って入った場合は、racker からは WSL タブに見えないため、WSL 内のパス（`/tmp/…` など）は開けません。`/mnt/c/...` 形式のパスは開けます。
- 開けなかった場合、今のところ画面上には何も表示されません（無反応に見えます）。

### 既知の問題

- 画像そのものをターミナル内に描画する機能（インライン表示）は引き続き未対応です。
- Authenticode コード署名は未対応のため、SmartScreen 警告は引き続き出ます。「詳細情報」→「実行」で続行可能。
